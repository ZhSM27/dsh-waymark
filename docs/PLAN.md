# Waymark 执行计划

## 授权与阶段门

用户已确认继续独立开发，并将定位扩展为综合性 Agent 工作流程优化插件。此前发现同类插件的停止条件已向用户报告；本次授权允许继续。每个 Phase 结束必须汇报并等待用户确认，不跨阶段。未经明确授权不 push、publish 或修改远端仓库。

## 产品边界

统一流程：会话证据 → 过程诊断 → 改进提案 → 人工确认 → 后续效果比较。

综合化通过模块实现，保持独立禁用能力。整合现有插件的能力方向，不默认安装、捆绑或执行第三方插件。引用、复用代码时逐文件核对许可并保留归属。

| 模块 | 来源参考 | 规划 |
|---|---|---|
| Audit | dsh-session-audit | 会话统计、失败与验证信号、历史读取 |
| Diagnose | 原 dsh-retro 方案 | 状态变化感知的失败过程、重复内容、大输出与纠偏 |
| Evidence | dsh-context-provenance | 观察/估算/未知分级、明确证据边界 |
| Improve | StellatoL/retro | 少量带条件与证据的规则提案，人工采纳 |
| Evaluate | 本项目 | 用户反馈、误报分析、规则采纳后的描述性比较 |
| Guard（后续） | dsh-agent-loop-guard | 先离线回放与仅观察；运行中警告/阻断须另行确认设计 |

余额、计费面板、自动压缩、会话交接、模型调用、自动修改 AGENTS.md、Obsidian/博客发布、Claude/Codex 适配均不纳入 v0.1。未来需要扩展时另行列入阶段。

## 分阶段执行

0. 调研：安装并固定 dsh；审查安装包、官方文档及参考源码；完成 SCHEMA、Open questions、只读事件计数探针。必须有一个真实保存会话的读取证据才算完整验收。没有数据则报告未完成，禁止用合成日志冒充真实会话。
1. 核心：零 dsh 依赖的统一事件、R1/R3、证据与估算、纯报告渲染；合成测试包含正常迭代不误报。
2. 接入：dsh 适配；暂定 `/waymark retro [id|last]`，避免现有 `/retro` 冲突；本地安装并展示真实报告。
3. 完整诊断：R2/R4、范围/内容重复、配置校验、JSON 与显式 Markdown 导出、条件化规则提案；诊断报告默认最多三项。
4. 验证与发布准备：最近十个真实会话逐条人工评议，增加未报告片段抽查；分规则报告样本量与认同比例。低于 50% 收紧重测，高置信度 80% 为目标而非已达成绩。新增会话用于后续检验。准备 MIT、版本 0.1.0、keywords、topic 清单并等待发布授权。

后续：实时观察、上下文暴露分析、跨会话效果评估、交互反馈。不得仅凭更少调用数宣称质量提升；需同时比较任务完成与验证结果。

## 统计契约（Phase 0 待安装源复核）

- 保留 session/seq/turn/step 与证据来源；结果分成功、失败、未知。
- 内容 token 估算与模型请求用量分开；未知不当作零。
- R1/R2 浪费仅统计第一次之后的重复调用及其结果；总额按调用身份去重。
- R3 大不等于无用，R4 只作低置信度辅助，不全部计入可避免体积。
- 原会话与当前模型可见内容、继承历史分开描述；不声称完整因果解释。
- 用户消息需识别来源，排除系统注入。重复读取需考虑成功修改和读取范围；外部状态不可观测时注明限制。

## 工程约束

TypeScript、pnpm、tsdown；core 无 dsh 依赖。所有测试夹具独立合成，不提交真实会话、私人路径、密钥或个人信息。调研环境和真实报告放在 git 忽略目录。每阶段小步本地提交，汇报测试、版本与未决问题。
